# 05 客户端 MVP 设计

日期：2026-10-16。本文只做设计，**不进入批量实现**（与目标约束一致）。
所有"可做"的判断都以 04 的验证等级为准；凡是"未验证"的接口，一律不进入 MVP 承诺范围。

---

## 0. 现状：已有一个预览版实现（本文档的作用是界定"可承诺边界"）

本仓库**已经存在**可运行的客户端实现，本文档不是"从零开始的设计"：

- `probe/`：一次性连接验证原型（2026-10-15 完成真实独立登录与自发自收核对）；
- `coremail_desktop/`：桌面客户端预览版，已打包为 `dist/CoremailDesktopPreview/CoremailDesktopPreview.exe`；
- 回归套件 `tests/`，README 记录最新 **197 项（195 通过 / 2 跳过）**；
- 已接通并通过本人邮箱实测：登录、文件夹、列表、阅读、写信、本机草稿（DPAPI 加密）、附件另存、回复/回复全部、已读/星标；
- **未完成**：附件上传端到端、移动/删除、服务端搜索、证书加密发送。

因此本文档的目标是：**用已验证证据划定"可以对客户承诺的能力边界"**，
并明确哪些能力目前只有预览实现、不得对外承诺（见 §1 非目标、§5 红线）。

> 验证等级的判定与"谁验证的"说明见 04 §0。

### 关于"AI 原生"的补充（本轮实测，供后续迭代定位）

官方客户端已内置一整套 AI 能力面（证据：`app/locale/webai.zh_CN.js`，见 02 §3.1.1）：
**13 个提示词操作**（写信、会议邀请、全文/简化校对、行内补全与句中补全、按语调改写、限字数改写、翻译、
总结、按标签生成 HTML），且每个操作都带**输出格式硬约束**（HTML 禁 Markdown / JSON `{"targetMessage":…}` / `ANSWER: …`）；
提供方选择是**本地优先**——若本机 Ollama 上存在匹配 `/deepseek.*/` 的模型就走本地，否则回落到云端 DeepSeek。

对本项目的意义：M1 阶段若要体现"AI 原生"，**最小可信集合是"写信 + 校对 + 总结"三个操作**，
并且必须同样遵守"输出格式约束"与"不静默把内容发到云端"这两条；完整 13 项列为 M3。

## 1. 目标与非目标

### 目标（MVP 必须达成）

1. 用**自己的会话**登录公司 Coremail 部署（`https://newmail.inspur.com/coremail/`），不使用浏览器或官方客户端的 cookie/sid/设备密钥。
2. 只读闭环：文件夹 → 邮件列表（分页）→ 原始 MIME 收取 → 本地解析与展示。
3. 写闭环：已读/未读、星标、移动到文件夹、发信（纯文本 + 附件）、回复/回复全部、本机草稿。
4. 服务端搜索。
5. 全程**如实呈现失败**：不把 `S_OK` 当投递成功，不在会话失效时静默重试，不对未验证接口做降级。

### 非目标（MVP 明确不做）

| 不做 | 原因 |
| --- | --- |
| 设备绑定/令牌签名登录 | 签名原文与算法未恢复；伪造设备身份违反红线 |
| 二次认证自动闭环 | 挑战-提交状态机未验证 |
| 实时推送 | 通道已实测（Socket.IO over wss，见 03 §2.4），但握手鉴权、命名空间、事件格式未验证 |
| S/MIME / 国密加密发送 | 加密提交契约未验证，禁止降级为明文 |
| 读取或迁移 `mail.edbx2` | 加密算法与密钥派生未确认 |
| 组织架构增量同步 | 版本号/缓存格式未验证 |
| 共享邮箱读写 | `mboxa` 上下文语义未验证 |
| 日历、网盘、AI/Lunkr | 超出 MVP 范围（但 AI 的**能力面已摸清**，见下） |
## 2. 协议策略

**主后端：Coremail 私有 HTTP JSON-RPC**（已实测可用）。
**预留但不实现其他后端**：IMAP4/SMTP/EWS 在二进制中存在。
【已观察】本部署的服务端能力声明里 `supportIMAP: true`——**服务器确实提供 IMAP**，
所以"用 IMAP 作为替代后端"在协议层面是可行的候选；但客户端自身没有使用它（日志中零 IMAP 会话），
且本项目的已验证路径全部在私有协议上，因此 MVP 仍只实现 Coremail HTTP，传输层做成可插拔接口。

【由服务端能力声明直接决定的 MVP 范围调整】：

| 能力 | 值 | 对 MVP 的影响 |
| --- | --- | --- |
| `supportNetfolder` / `supportTrs` | `false` | 网盘（`nf:*`）与文件中转站在本部署未启用 → `nf:*`、`upload:moveToNetDisk*` **排除出 MVP**。注意：`xnf:*` **不受该开关控制**（`xnf:getConfig` 在关闭状态下仍被调用 106 次），故 `xnf:*` 保持"未知"，不作排除 |
| `supportSecurityLevel` | `false` | 密级功能关闭 → compose 的 `ctrls`/CM-SECURITY 路径预计为空，但**仍需一次实测确认** |
| `supportFulltextSearch` | `true` | 服务端全文搜索可用 → 搜索纳入 MVP（已有契约验证） |
| `supportThreadingView` | `true` | 会话线程可用 → 后续迭代项 |
| `supportRecallMail` | `true` | 召回可用 → 列为 P1，不阻塞 MVP |
| `supportAuthorizedDevice` + `enableAuth2Lock` | `true` | 登录必须能处理设备绑定/二次认证提示（不实现绕过） |
| `supportWSMsgNotify` | `true` | 推送走 WS 通知 → 列为 P2 |

传输层硬性约定（来自 02 的已证事实）：

| 项 | 值 |
| --- | --- |
| 端点 | `POST {base}/s/json?func=<模块>:<方法>&sid=<sid>` |
| 正文 | Coremail JSON；扩展日期 `!!date '<YYYY-MM-DD HH:mm:ss>'` 需专用词法处理（只在字符串外识别，禁止 `eval`） |
| Header | 请求 `text/x-json`（或 `application/x-cm-json`）；`Accept: text/x-json` |
| 会话 | 内存 CookieJar + `sid` 双通道；只在同一 origin 内联跳转 |
| 成功判定 | `code == "S_OK"`；其余按 04/03 的码表分类 |

## 3. 能力分层与接口映射

每一层只列出**已验证（真机或契约）**的接口；括号内标注证据等级。

### L0 只读（MVP 第一里程碑）

| 功能 | 接口 | 状态 |
| --- | --- | --- |
| 登录 | `POST /coremail/index.jsp?cus=1` 表单 | 真机实测 |
| 文件夹 | `mbox:getAllFolders` | 真机实测（9 个文件夹） |
| 列表 | `mbox:listMessages`（`fid/start/limit/mode/order/desc/returnTotal`） | 真机实测 |
| 正文 | `mbox:getMessageData&mid=&mode=text` → 本地 MIME 解析 | 真机实测（41 KB MIME） |
| 账号属性 | `user:getAttrs`（日志 14,066 次，字段含 `attrIds`/`optionalAttrIds`） | 日志观测 |

### L1 写操作（第二里程碑）

| 功能 | 接口 | 状态 |
| --- | --- | --- |
| 已读/星标 | `mbox:updateMessageInfos`（`attrs.flags.read/flagged` + `returnOriginalMsgInfos` 回读确认） | 真机实测 |
| 移动 | `mbox:updateMessageInfos`（`attrs.fid`） | 契约验证 |
| 发信 | `%mbox/compose`：`action=continue` 建会话 → `action=deliver` | 真机实测（自发自收） |
| 回复/回复全部 | 回复会话 + 父 `Message-ID` 校验（`In-Reply-To`/`References`） | 真机实测（4 封） |
| 本机草稿 | 本地加密存储（DPAPI），不依赖服务器草稿 | 已有实现 |
| 删除 | `mbox:deleteMessages`（`ids`/`localArchive`） | 日志观测，**未做真机破坏性验证** |

### L2 附件（第三里程碑）

| 功能 | 接口 | 状态 |
| --- | --- | --- |
| 上传 | `upload:prepare` → `func=directData`（`composeId`/`attachmentId`/`offset` 分片） | 行为已在日志观测（分块续传，176 次成对，见 03 §3.3），端到端验收未完成 |
| 下载（收） | MIME 内附件导出（**已验证**：3 封邮件/8 个附件/大小一致）＋ 服务端 `viewDownloadFile.jsp?key=`（**未验证**） | URL 与 `key` 由原生内部构造（03 §3.3），须抓包或反编译；MVP 先只做 MIME 内附件导出 |
| 大附件 / 网盘 | `nf:*` | 本部署能力声明关闭（`supportNetfolder:false`），不做；MVP 先只支持 MIME 内附件 |

### L3 增强（不在 MVP 承诺内）

服务端搜索（已契约验证，可提前纳入）、共享邮箱、标签、召回、投递状态、推送、离线库。

## 4. 架构建议

```
+------------------------------- UI (桌面) -------------------------------+
|  登录 / 文件夹树 / 列表 / 阅读 / 写信 / 设置                             |
+--------------------------------+---------------------------------------+
| 应用服务层                     | 草稿·发件记录（本地加密）              |
| 会话协调、分页、去重、失败分类 | 附件校验、MIME 解析与净化              |
+--------------------------------+---------------------------------------+
| Transport (可插拔)             |  Coremail HTTP JSON-RPC（MVP 唯一实现）|
|  origin 白名单、超时、重试策略 |  !!date 词法、错误码分类               |
+--------------------------------+---------------------------------------+
| 本地库 (自定义，非 edbx2)      |  缓存/离线队列（MVP 可只做缓存）        |
+-------------------------------------------------------------------------+
```

关键设计约束（均为已证事实的直接推论）：

1. **同源严格绑定**：所有请求与重定向必须与登录 origin 一致，否则拒绝（原客户端有 `UNSAFE_ORIGIN` 类保护，自研实现必须自带）。
2. **写操作必须回读确认**：`updateMessageInfos` 必须带 `returnOriginalMsgInfos` 并核对目标 ID 才更新界面（已实测的可靠模式）。
3. **发信两阶段**：先 `continue` 拿 composeId，再 `deliver`；`S_OK` 只更新为"服务器已接受"，投递另行核对。
4. **失败分类固定文案**：不做智能重试；网络类错误可对只读请求重试（有上限），写请求不自动重放。
5. **本地库自建**：不使用也不解析 `mail.edbx2`/`address.edbx2`；避免与官方客户端互相破坏。
   依据：四个 `.edbx2` 共享同一 16 字节固定头、前 4 KiB 无 SQLite 魔数（见 01 §5.2.1），
   既不能按 SQLite 直接打开，也无法在未掌握格式与密钥时安全读写。

## 5. 里程碑与验收标准

| 里程碑 | 内容 | 验收（必须可复现） |
| --- | --- | --- |
| M1 只读 | L0 全部 | 独立登录 + 读取 9 个文件夹 + 至少 50 条摘要 + 1 封真实 MIME，输出脱敏报告 |
| M2 写 | L1 全部 | 发信自发自收（收件箱唯一标记回查）+ 回复 + 标记设置/回读/恢复 |
| M3 附件 | L2 上传 | 带附件发信并回收，核对附件字节哈希一致 |
| M4 只读增强 | 服务端搜索、投递状态查询 | 搜索按唯一标记命中；投递状态与实测一致性说明 |

每个里程碑的验收产物必须落到 `analysis/*-contract-*.json` 形式（延续现有做法），并同步更新 04。

## 6. 红线

1. 不复制、不伪造官方客户端的设备身份、密钥或签名。
2. 不使用他人凭据；仅本人在授权账号上验证，测试邮件保留不删。
3. 加密提交接口未验证前，**不得**静默降级为明文发送。
4. 遥测类接口（`cim.common:clickLog`、Lunkr `log/report`、跟踪数据桥接命令）默认关闭。
5. 原始客户端日志与账号数据不得入库、外发或写入交付物。

## 7. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 仅在一个部署（inspur）验证 | 换服务器可能不兼容 | 传输层与端点可配置；把 XT3/XT5/XT6 差异列入 06 待验证 |
| 会话/认证策略变化（设备绑定、2FA 强制） | 登录失败 | 明确阻断并提示，不做绕过 |
| 接口字段随版本变化 | 写操作失败 | 写操作全部回读确认；错误按码表分类 |
| 日志与网页证据不覆盖 schema | 需要更多真机契约验证 | 每新增一个接口先做契约验证，再写实现 |
