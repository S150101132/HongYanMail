# 本地存档（官方客户端 archmails）— 设计文档

日期：2026-10-20　状态：已实现完整版，待真机验收（[记录](../../releases/2026-10-20-local-archive.md)）。用户确认：引入 zstandard、文件夹 D:\work\email\wangbiao@inspur.com、第一版做完整版

## 1. 背景与目标

官方 Coremail 客户端的「本地存档」会把邮件从服务器移到本机，界面上显示「本邮件仅存在于此计算机」。这些邮件服务器上已经没有了，所以鸿雁的服务器搜索和「问邮箱」都找不到。例子：2026-02-10 的「BI UAT Sign-Off Confirmation」。

目标是让鸿雁**只读**地使用这些存档：

1. 「问邮箱」同时搜索服务器和本地存档，出处卡片能打开存档里的邮件。
2. 左侧栏增加「本地存档」：可以按时间浏览、搜索、阅读，也能打开、保存附件。
3. 普通搜索的结果里也包含本地存档的邮件，并标出「本地存档」。

不做的事：

- 不写入、移动或删除官方客户端的任何文件，不把存档邮件传回服务器。
- 不读官方客户端的账号、密码和设置文件（`*.sdat`、`*.edbx2`、`cache.dat`）。
- 不读 `backup.pst`（Outlook 历史备份）。
- 不读 `mails/`：那是官方客户端对服务器邮件的缓存，和服务器内容重复。

## 2. 已核实的事实

依据：`analysis/archive-shape-2026-10-20.json`。只读了文件头，没有解压，也没有读取内容。

| 项 | 结果 |
| --- | --- |
| 位置 | `D:\work\email\wangbiao@inspur.com\archmails\00.cmpack` … `ff.cmpack`，共 256 个包 |
| 规模 | 共 3568 封邮件、5.28 GB（主要是附件）；每包最多 16 封，有 9 个包超过 15 封（目录有扩展页） |
| 文件头 | 256 个包全部是 `CMDR` 开头，页大小 1024，没有不认识的格式 |
| 官方客户端 | 仍在使用中（`mail.edbx2` 等今天有修改），存档包的修改时间是 2026-10-12 |

格式参考用户已有并验证过的工具 `0-0-NG-TASK/tools/coremail-reader/decode_cache.mjs`：

```text
.cmpack  = CMDR 目录（每条 64 字节：数据页号 + 记录名 *.data）→ PGFN 页（长度、连续数据区）
记录      = cmms 头（原文总长）+ 若干 CMCD 块（每块是一个 Zstandard 帧）+ CMCT 块表
原文      = 拼接解压结果，截到总长，再按单字节 XOR 掩码还原（用 RFC 头部来识别掩码）
```

还原出来的是完整的 RFC 822 原文，鸿雁现有的 `parse_mime` 可以直接解析。S/MIME 加密邮件也一样是原文，解锁个人证书后可以解密。

## 3. 关键决策

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 解压 | 引入 `zstandard`（PyPI，BSD-3，Windows wheel 自带 libzstd，约 1 MB） | Python 3.12 标准库没有 Zstandard（3.14 才有）；纯 Python 实现太慢；也不能依赖 Node |
| 检索方式 | 首次建立**加密的本地目录**：每封一行，包括主题、发件人、收件人、时间、附件名，以及截断到约 20 KB 的纯文本。查询时在内存里做子串匹配 | 只有 3568 封，扫一遍是毫秒级，不需要 FTS 或向量库。和现有缓存一样以 AES-GCM 密文落盘，没有明文索引 |
| 原文 | 不复制。打开或阅读时按（包、记录位置）重新读取并解压，再核对 SHA-256 | 5.3 GB 不应该复制一份；核对指纹可以发现官方客户端改动过的包 |
| 增量 | 按包的大小和修改时间判断；没变化的包整包跳过，变化的包整包重建 | 包少、改动少，简单可靠 |
| 邮件 ID | `arc:<原文 SHA-256 前 24 位>`，按 Message-ID 去重 | 沿用 `eml:` 只读邮件的机制：只读、不在服务器上 |
| 加密邮件 | 目录里只记录信封信息（主题、人、时间），不解密正文 | 和服务器搜索一样：问邮箱默认不读取，单封允许 |
| 存档位置 | 设置里由用户选择文件夹（这台电脑填 `D:\work\email\wangbiao@inspur.com`）；只读其中的 `archmails\*.cmpack` | 不猜路径，不扫描整个 `D:\work\email` |

## 4. 架构

```text
coremail_desktop/archive/
  reader.py   CMDR/PGFN/cmms/CMCD/CMCT 解析、Zstandard 解压、XOR 还原；带大小上限，格式不符就报错，不猜
  catalog.py  建立和增量更新加密目录（行：id、包、偏移、长度、sha256、信封、纯文本、是否加密）
backend.py    archive_status / archive_scan / archive_view / search 合并 / _raw 支持 arc: ID
ai/tools.py   search_mail 增加 source: all | server | archive（默认 all），结果里标明来源
web           侧栏「本地存档」、设置项（选择文件夹、扫描进度、封数、上次扫描时间）、列表与搜索结果标签
```

- 扫描在后台线程运行，进度推送到设置页。首次扫描预计 1～3 分钟（解压 5 GB 约 5～10 秒，大部分时间花在 3568 封邮件的 MIME 解析上），以实测为准。
- 读文件前后各取一次大小和修改时间，不一致就跳过这个包，下次再试（官方客户端可能正在写）。
- 单包上限 512 MB、单封解压输出上限 128 MB，与参考工具相同。

## 5. 安全与隐私

- 只打开 `archmails\*.cmpack` 进行读取（`rb`），不写入、不加锁。
- 目录文件 `archive.db` 中每行都用 AES-GCM 加密，密钥受 DPAPI 保护，与邮件缓存相同。删除这个文件只会让鸿雁重新扫描，不影响官方客户端。
- 存档邮件按只读邮件显示：可以回复和转发（生成新邮件），但不能移动、删除或改标记。
- 问邮箱的规则不变：只送清洗后的文本，加密邮件默认不读取。
- 错误只显示固定码：`ARCHIVE_NOT_FOUND`、`ARCHIVE_UNSUPPORTED`、`ARCHIVE_CHANGED`、`ARCHIVE_SCANNING`。

## 6. 分步实施

1. `archive/reader.py` 和测试：用合成的 CMDR 包测试（测试里用 `zstandard` 压缩生成），覆盖目录扩展页、多块记录、掩码、截断和超限。
2. `catalog.py`：加密目录、增量扫描、Message-ID 去重。在真实存档上只读运行一次，只记录封数、失败数和耗时到 `analysis/`。
3. backend 和问邮箱：`arc:` 邮件可以打开和阅读，`search_mail` 合并两个来源。
4. 界面：设置项、侧栏「本地存档」列表和搜索标签。
5. 打包：`zstandard` 加入 PyInstaller，执行 `build.ps1` 检查；写 release note。
