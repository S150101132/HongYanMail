# 个人工作助理：在对话里看任务、改任务、从任务起草邮件 — 设计

日期：2026-10-21　状态：W1–W4 已完成，待真机验收（[W1](../../releases/2026-10-21-assistant-w1.md)、[W2](../../releases/2026-10-21-assistant-w2.md)、[W3](../../releases/2026-10-21-assistant-w3.md)、[W4](../../releases/2026-10-21-assistant-w4.md) 记录）（第 9 节问题 2026-10-21 用户确认全部按建议；另定回信可以选收件人组，见 4.3）

依据：用户 2026-10-21 提出的场景；建立在 [AI 优先的交互 · 整体计划](2026-10-21-ai-first-interaction-plan.md) 的 A1 对话侧栏、[任务中心](2026-10-20-task-center-design.md) 和 [理解层](2026-10-21-mail-understanding-memory-design.md) M1 之上。

## 1. 场景

用户在对话侧栏里：

1. 问"现在有什么任务，哪些需要我做" → 列出要做的任务和「待我处理」的邮件，可以点开。
2. 看任务时发现发件人给的背景不全 → 说"回个邮件问问具体信息" → 助理找到这个任务的最后一封邮件，起草一封回复，打开写信窗口，由用户检查后发出。
3. 说"这个任务已完成" → 助理给出「完成并归档」的预览，确认后执行。
4. 说"给客户回邮件" → 回复这个任务会话的最后一封；或说"起草一封发给相关客户" → 新写一封，收件人是会话里的外部联系人。
5. 用户没说要回信，但任务刚完成或改了状态，会话里最后一封是对方发的、用户还没回 → 助理问一句"要给某某回一封告诉他已完成吗？"

## 2. 已有的和缺的

| 能力 | 已有 | 缺 |
| --- | --- | --- |
| 多轮对话、邮件编号跨轮有效 | A1 侧栏（`ai/agent.py`、`MailboxTools`） | 任务编号；"当前任务" |
| 查任务、改任务（预览后确认） | `tasks/assistant.py` 的计划、`center.preview` / `run_plan` | 只能在任务中心页用，侧栏调不到 |
| 待我处理 | `understand_view('act')`、理解卡片 | 侧栏调不到；和任务去重 |
| 任务关联的邮件 | `store.links(task_id)`：`mid`、`messageId`、`subject`、`date` | 从关联邮件找到会话的最后一封（`backend.thread`） |
| 起草回复 | `draft_reply(mid, idea, note)`，收件人、主题、加密按普通回复 | 从对话触发并打开写信窗口；新写一封 |
| 收件人组 | v0.7：本机加密保存（`recipient_groups`），`apply_recipient_groups` 把组员按主送 / 抄送填进写信窗口 | 起草时按组选收件人；按会话参与人推荐组 |
| 完成后提醒回信 | — | 全部新做 |

## 3. 原则

沿用整体计划第 1 节和「AI 功能的共同前提」，这里特别强调：

1. **AI 永远不能发信**。起草的结果只是写信窗口里的草稿，收件人、加密开关都在窗口上，由用户点发送。
2. **任务的写操作都走任务助手的计划**：预览卡片 → 用户点「执行」→ `run_plan`，和任务中心页同一条路径、同一套校验，不另写一套。
3. **提醒只在用户刚做完一件事时出现**（完成任务、改状态、记进展），每次最多一条，点「不用」就不再为这条任务提醒；不在后台定时弹出。
4. 邮件正文和任务字段都当作不可信数据（任务内容可能是从邮件复制来的）：包在随机标记里，其中的指令无效。

## 4. 侧栏变成「助理」

### 4.1 一个对话，两类编号

- 邮件仍是 `[mN]`，任务用 `[tN]`（N 是任务中心的编号）。回答里的任务引用可点击，在任务中心打开那条任务。
- **当前任务**：和「附带当前邮件」一样，在任务中心选中一条任务时，输入框上方显示「附带当前任务：#12 …」；问题里的"这个任务""该任务"指它。没有附带时，指上一轮回答里唯一提到的任务；有两条以上就反问。
- 侧栏在邮件页和任务中心页都能打开（Ctrl+J）。任务中心页原来的命令框保留，作为"只改任务"的快捷入口。

### 4.2 工具集（`ai/tools.py`，`MailboxTools` 之外新增 `AssistantTools`）

只读工具，AI 可以直接调用：

| 工具 | 返回 |
| --- | --- |
| `list_tasks(view, query, mine)` | 任务列表（编号、系统、内容前 80 字、状态、截止日期、负责人、下一步）；`mine` 只要负责人为空或是用户本人的 |
| `read_task(id)` | 一条任务的全部字段、最近 5 条进展、关联邮件（`[mN]` 编号、主题、日期） |
| `pending_mail()` | 「待我处理」的理解卡片（要我做什么、截止日期、项目），已转为任务的不重复列出 |
| `task_thread(id)` | 任务关联邮件所在会话，按时间排好；标出最后一封、最后一封是谁发的、用户是否已回复过、会话里的外部联系人（显示名 + 域名） |
| `list_groups()` | 收件人组：组编号 `[gN]`、组名、人数、主送 / 抄送人数、成员的域名；**不给 AI 地址**。按与当前任务会话参与人的重合人数排序，标出重合几人 |
| 原有 `search_mail` / `read_mail` / `find_contact` | 不变 |

提议工具，**只返回计划，不执行**：

| 工具 | 计划 |
| --- | --- |
| `plan_tasks(actions)` | 任务助手的 actions（progress / update / complete / cancel / reopen / create）原样经 `check_actions`、`center.preview` |
| `draft_reply(mid, purpose, points, group)` | 回复哪一封（必须是已知编号）、目的（询问 / 告知完成 / 其他）、要写的要点；`group` 可选，是 `list_groups` 返回过的组编号 |
| `draft_new(to, group, subject, purpose, points)` | 新邮件；`to` 只能是本对话里工具返回过的联系人编号，`group` 同上，二者至少一个 |

### 4.3 预览卡片

- **任务计划**：和任务中心页的预览一样（字段前后对比、错误码说明），「执行」「修改」两个按钮。
- **起草**：显示"回复 张三（@客户域名）最后一封：《主题》，目的：询问具体信息"和要点。点「起草」后调 `draft_reply`（流式），完成后打开写信窗口：
  - 回复：`compose('reply' 或 'reply_all', mid)` 得到收件人、主题、引用和加密状态，正文换成 AI 的草稿。
  - 新邮件：`compose('new')`，收件人填计划里的联系人；外部收件人醒目标出，加密按现有规则（同事默认加密，外部默认不加密）。
- **收件人可以选收件人组**：起草卡片上有一行「回复给」，选项是：
  - 「按原邮件回复」（回复发件人）、「全部回复」：收件人来自普通回复，是默认值。
  - 收件人组：列出 `list_groups` 排在前面的组（和这个会话参与人重合最多的在前，显示"重合 3 人"），以及「其他组…」打开全部组。用户说了组名（"回给沙特项目组"）时，AI 在计划里带上那个组，卡片上预先选好。
  - 选了组：仍然用 `compose('reply', mid)` 的主题、引用和会话关联（In-Reply-To），但主送、抄送清空后按组填写（`apply_recipient_groups(group_ids, to=[], cc=[])`，组员的主送 / 抄送照组里的设置）；也可以勾选「保留原发件人」，原发件人留在主送。
  - 加密照旧按最终的收件人决定（同事默认加密，外部默认不加密），组里有外部地址时卡片上醒目标出"含外部 N 人"。
  - 这条任务上次选过的组（存在任务的 kv 里，只存组编号）下次作为默认值；组被删了就回到「按原邮件回复」。
- 写信窗口标出「助理起草」。草稿 **发出后**（`send` 成功，或进入待发队列），侧栏提议记一条进展，例如"已发邮件向张三询问 X，等待回复"，作为 `progress` 计划等用户确认；没发出就不提。

### 4.4 提醒回信

- 条件（后端判断，不调 AI）：任务计划执行成功，操作是 complete、改状态或 progress；这条任务有关联会话；会话最后一封不是用户发的；最后一封之后用户没有回过。
- 侧栏在执行结果下面显示一行："最后一封是张三 10-19 发的，你还没回。要回一封告诉他已完成吗？"，按钮「起草」「不用」。
- 「起草」等于用户说了"给他回一封，告知 <这次的操作>"，走 4.3；「不用」记在这条任务上（`tasks` 的 kv），以后同一个会话最后一封没变就不再提。

## 5. 一句话怎么处理

| 用户说 | 助理做 |
| --- | --- |
| 现在有什么任务 / 哪些要我做 | `list_tasks(mine=true)` + `pending_mail()`，按已到期、有截止日期、其他排序；回答里每条带 `[tN]` / `[mN]` |
| 回个邮件问问具体信息 | 确定当前任务 → `task_thread` → `draft_reply(最后一封, 询问, 要点)`。要点由 AI 根据任务内容和会话列出"还缺什么"，用户可以在卡片上改 |
| 已完成该任务 | `plan_tasks([complete])` → 预览 → 执行 → 4.4 判断是否提醒 |
| 给客户回邮件 | 当前任务的会话里，最后一封外部联系人发的邮件；有多个外部联系人时让用户选；卡片的「回复给」可改选收件人组 |
| 回给沙特项目组 / 抄送给某某组 | `list_groups` 找到组名对应的组（名字不唯一或找不到就反问），`draft_reply(…, group)` |
| 起草一封发给相关客户 | `draft_new`，收件人候选是会话里的外部联系人和重合最多的收件人组，用户在卡片上勾选 |
| 这个任务没关联邮件 | `task_thread` 返回空 → 按任务内容 `search_mail`，列出最多 5 封候选让用户选；选中后提议「关联邮件」（走现有 `task_link`） |

## 8. 验收

- **自动化**：任务编号只能用工具返回过的；没附带当前任务又有两条可能时反问；`plan_tasks` 不确认不写；`draft_reply` 只接受已知邮件编号；新邮件收件人只能来自工具返回；组编号只能来自 `list_groups`，AI 拿不到组员地址；选组后主送 / 抄送按组、主题和会话关联按原邮件、加密按最终收件人；任务记住上次的组、组删除后回到默认；提醒条件（最后一封是谁、用户回过没有、「不用」后不再提）；发出后才提议记进展；任务字段中的指令不生效。
- **演示走查**：`tools/screenshot_app.py` 补"有什么要我做"、起草预览、写信窗口、完成后提醒。
- **真机**（用户从资源管理器启动，只记是否通过）：
  1. 问"哪些需要我做"，列出的任务条数与任务中心一致。
  2. 对一条有关联邮件的任务说"回个邮件问问具体信息"，写信窗口回复的是会话最后一封，收件人正确；这一步只起草不发。
  3. 同一任务说"回给 <某收件人组>"，写信窗口主送 / 抄送与组一致、主题是「回复：…」、加密开关符合规则；只起草不发。
  4. 说"已完成"，预览正确，执行后出现提醒；点「不用」后再记一次进展不再提醒。
