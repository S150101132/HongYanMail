# 「今天」页与统一一个 AI 入口（R2a、R2b）— 设计文档

日期：2026-10-22　状态：设计中（R0 试用一周后按摩擦记录修订，再开工）
依据：路线图 R2a、R2b；用户 2026-10-22 从产品角度复盘「整个流程用起来不顺」，并定下原则「最好的工作方式就是最简单的」。

## 1. 原则：做减法

用户的原话是「最好的工作方式就是最简单的」。这次设计按下面四条取舍，以后评审 R2 的改动也用它们对照：

1. **每一步都比现在少一样东西。** 加一个页面，就要撤掉至少一个入口或一块界面；只加不减的方案不做。
2. **一件事只有一个地方。** 要做的事在一张清单里，对话在一个侧栏里，不在两处各放一份。
3. **默认不打扰。** 能直接做、做错了能撤销的，就直接做，在提示里给「撤销」；只有发信、改状态、删除、对外起草才需要确认。
4. **不新增 AI 调用。** 今天页只汇总已有数据（理解层、任务中心、催办），打开它不花 token。

## 2. 现在的问题

| 问题 | 现状 |
| --- | --- |
| 「我要做的事」分成四处 | 收件箱筛选「要我做」、任务中心、待确认建议（任务详情里）、已发送筛选「等回复」 |
| 打开应用没有起点 | 默认进收件箱，要自己去这几处各看一遍 |
| AI 入口有 6 个 | 搜索框旁 ✨、Ctrl+K、Ctrl+J 侧栏、阅读栏 AI 菜单、阅读提示条、任务页「问问鸿雁」输入框；任务页输入框和侧栏能力重叠，上下文不互通 |
| 收件箱列表头越来越重 | 「本周需要知道」概括占了列表上方一大块 |

## 3. R2a「今天」页

### 3.1 只有一张清单

今天页就是**一张清单：现在该我做的事**，邮件和任务混在一起，按截止日期排。没有四个区块、没有卡片、没有图表。

| 进清单的 | 条件 | 数据来源 |
| --- | --- | --- |
| 要我做的邮件 | 理解层判断「要我做」、AI 确定、未处理 | `understand_view('act')` |
| 任务 | 未完成，且已逾期、今天到期或 3 天内到期 | `tasks_overview('open')` 的计划完成日期 |

排序：已逾期 → 按截止日期 → 没有截止日期的（按最新）。每行一个记号区分邮件（✉）和任务（#编号），右侧显示截止日期，逾期标红。

清单上方一行小字，其余东西都只是**一个数字链接**，点了才去：

> 10 月 22 日 周四 · 逾期 2 · 今天 3　　在等别人 4 · 待我确认 2 · 本周概括

- **在等别人**：催办（`followups()`）和「受阻」的任务，点开在同一位置换成这张清单，左上「← 今天」返回。
- **待我确认**：任务中心的待确认建议（`tasks_pending()`）和工作记忆的任务候选。点开同样换成清单，每行「采纳 / 不用」，顶部「全部采纳」「全部不用」，执行后提示里可撤销。
- **本周概括**：`memory_week_brief`，点开显示，从收件箱列表头**撤掉**。

数字为 0 的不显示。

### 3.2 布局：沿用三栏

今天页不是新的整页视图，而是左侧栏的一项（「本机」最上面，带数字），用现有的邮件三栏：

- **中间栏**是这张清单（复用邮件列表的行样式和分组标题）。
- **右侧**选中邮件时就是现在的阅读栏；选中任务时显示**一张简短的任务卡**：编号、标题、状态、计划完成、最新进展，按钮「记进展」「完成」「在任务中心打开」。任务卡复用 `task_get`，不做演进图、变更记录。

这样不用来回跳页面：在今天页里就能读邮件、回复、记进展、完成。

### 3.3 做完就消失

- 邮件：点「已处理」或回复发出后（R1a）从清单移走，提示「已处理 · 撤销」。
- 任务：「完成」后移走，沿用 P1 的「#N 不再受阻」提示。
- 清单清空时显示「今天没有要你做的事」，下面一行小字「在等别人 N」（有的话）。

### 3.4 默认首页

- 设置里加一项「启动时打开：今天 / 收件箱」，默认「今天」。
- 没开理解层时，清单里只有任务，顶部一行「开启『理解新邮件』后，要你做的邮件也会出现在这里」，链接到设置。
- 没导入任务时，只有邮件；两者都没有时显示开启指引。

### 3.5 撤掉什么

| 撤掉 | 去向 |
| --- | --- |
| 收件箱列表头的「本周需要知道」概括 | 今天页「本周概括」 |
| 任务详情里零散的待确认建议入口 | 今天页「待我确认」（任务详情仍显示和本任务有关的那几条） |
| 已发送列表头「等回复」筛选 | 今天页「在等别人」（命令框「只看等回复」保留，指向今天页） |

收件箱的「要我做」「知会」筛选**保留**：它们是看邮件时顺手用的，今天页是一天开始时用的。

### 3.6 后端

新增一个只读方法 `today_overview()`，汇总上面几个已有方法的结果，返回：

```
{'date': 'YYYY-MM-DD', 'rows': [{'kind': 'mail'|'task', 'id', 'title', 'due', 'overdue', ...}],
 'counts': {'overdue', 'today', 'waiting', 'confirm'}, 'understanding': bool, 'tasks': bool}
```

不调用 AI，不访问网络（只读缓存和任务库）。新邮件理解完、任务改动、标为已处理后，页面重新取一次。

## 4. R2b 统一一个 AI 入口

### 4.1 规则

- **对话只在右侧助理侧栏**（Ctrl+J）。侧栏自动带上当前所在的东西：当前邮件（已有）、当前任务（已有 `current_task`）、今天页（清单里的编号，让「先做哪件」「这几件里哪件最急」能回答）。
- **Ctrl+K 只管跳转和命令**：打开文件夹、打开任务、切换筛选、写信。输入的话不匹配任何命令时，最后一项「问鸿雁：…」把这句话交给侧栏（已有）。
- **阅读栏的「AI」按钮**只留一键动作：总结、起草回复；「问这封」打开侧栏并带上这封。

### 4.2 撤掉什么

| 撤掉 | 去向 |
| --- | --- |
| 任务页「问问鸿雁，或让它更新任务…」输入框和下面的对话区（T1） | 侧栏；在任务页打开侧栏时，空白提示换成任务的例句（「哪些任务受阻？」「333 今天完成了」） |
| 搜索框旁的 ✨ 按钮 | Ctrl+K 的「问鸿雁」和 Ctrl+J；搜索框只管搜索 |
| 任务页「只输入编号直接打开」 | Ctrl+K 输入编号 |

### 4.3 撤掉之前先补齐侧栏

任务页的任务助手（`tasks_command`，`tasks/assistant.py`）有几项侧栏的 `plan_tasks` 还没有，**先补进侧栏，再撤输入框**，否则就是倒退：

| 能力 | 任务页（T1 / T1b） | 侧栏现状 | 要做 |
| --- | --- | --- | --- |
| 新增前提 / 支线任务：新建 + 原任务写「依赖 #新编号」 | 有（占位 `#N1`，`resolve_refs`） | 没有占位编号 | `plan_tasks` 支持新建任务的占位编号，执行时替换 |
| 记进展前对照最新进展和最近 4 行历史，不重复记 | 有（规则 13） | 没有 | 把规则并入 `ai/agent.py` 的 `PLAN_RULES` |
| 确认时逐项勾选 | 有 | 计划卡片整体执行 | 计划卡片每项一个勾选框 |
| 追问后部分执行仍保留、告诉 AI 哪些已执行 | 有 | 侧栏多轮对话已保留上下文 | 执行结果回写到对话（核对一次即可） |

补齐后，`tasks_command` / `tasks_command_run` 只作为侧栏的内部实现或删除，`TASK_PLAN_REF` 等测试迁到侧栏的测试里。

### 4.4 不做

- 不让侧栏常驻占位：默认收起，按 Ctrl+J 或点「问这封」才出现。
- 不在侧栏里再做一套任务列表或邮件列表；侧栏只是对话。

## 5. 不做（整体）

- 不做晨报推送、不定时弹窗（7 号「每日晨报」仍是暂缓）。
- 不自动把邮件建成任务；候选只进「待我确认」。
- 不在今天页加图表、统计、甘特图。
- 不新增项目页面（统一「项目」概念另议，不在 R2 内）。

## 6. 待 R0 试用验证

开工前，用 R0 的摩擦记录回答这几个问题，答案改进本文：

1. 一天开始时，真的会先看「要我做 + 到期任务」吗？还是先扫收件箱？（决定默认首页）
2. 「3 天内到期」的范围合适吗？清单通常有多少行？超过 15 行要不要折叠？
3. 「待我确认」一天积多少条？如果很少，是否直接放回任务详情、连数字链接都不要。
4. 任务页的输入框和侧栏，实际各用了几次？用输入框时是否需要看着任务列表？

## 7. 测试

- `today_overview`：邮件和任务混排顺序、逾期 / 今天 / 3 天边界、已处理和已完成不出现、没开理解层 / 没导入任务时的返回、不调用 AI。
- 页面：今天页清单、数字链接切换与返回、任务卡按钮、做完移走与撤销、启动页设置。
- 侧栏：占位编号建前提任务并写依赖、进展查重、逐项勾选执行；任务页不再有输入框；搜索框没有 ✨。
- 演示数据（`--demo`）补齐今天页能看到的样例，截图存 `analysis/screens-r2/`。
