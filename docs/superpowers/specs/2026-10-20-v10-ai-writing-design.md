## 2. 流式输出

**做法**：`ChatClient.stream(messages, on_delta, cancelled, max_tokens)`，请求带 `stream: true` 和 `stream_options: {include_usage: true}`，逐行读 SSE（`data: {...}`，以 `data: [DONE]` 结束），把 `choices[0].delta.content` 交给 `on_delta`，返回 `(全文, tokens)`。

- 安全不变：HTTPS、不跟随跳转、HTTP 错误码映射同 `_http_code`；总长超过 `MAX_RESPONSE` 即 `AI_BAD_RESPONSE`。
- 重试只发生在**还没收到任何内容**之前；收到一部分后断开，报 `AI_UNAVAILABLE`，页面保留已显示的部分并标「未完成」。
- 超时：连接/首字 60 秒，之后每两段内容之间 30 秒。
- 取消：每收到一段检查一次 `cancelled()`，取消后关闭连接，报新错误码 `AI_CANCELED`（页面不当错误显示）。用量照算已返回的 token（服务端没给 usage 时记 0）。
- 传到页面：沿用问邮箱的做法，`shell.run` 为流式方法注入 `progress`，发 `aiStream` 事件 `{req, delta}`；页面按 `req`（页面生成的随机串）把文字追加到对应位置。每 80 ms 合并一次再发，避免事件过多。
- 用在哪：自由文本输出的功能——写信助手、起草回复的正文。「总结这封」「线程总结」「发送前检查」「任务计划」「周报」输出的是 JSON，要校验后才显示（周报的 HTML 由鸿雁按 JSON 生成），**不流式**，继续显示「正在生成…」（Q1）。
- 取消沿用已有错误码 `AI_CANCELLED`。

## 3. 总结整个线程

**入口**：阅读窗格的 AI 面板，当前邮件属于一个会话（`thread(mid)` 多于 1 封）时，「总结这封」旁边出现「总结整个会话（N 封）」。

**取材**：

- `backend.thread(mid)` 的全部邮件，按时间正序，最多 20 封（超过时取最早 2 封 + 最近 18 封，并在结果中注明省略）。
- 正文：没下载的先由邮件线程下载（`open_message(mid, mark_read=False)`，不标已读），AI 线程本身仍不下载。
- 每封只取「本封新写的部分」：`QUOTE_RE` 之后的引用全部去掉（会话里已经有原信），每封最多 3000 字，总量最多 30000 字，超出的从中间的邮件开始截短。
- 加密邮件：会话里有加密邮件时，一次询问「其中 N 封是加密邮件，是否一并发送？」；不同意就跳过这些邮件并在结果里注明。
- 本地存档里的会话邮件同样参与（只读）。

**输出（JSON，校验后显示）**：

```json
{"conclusion": "一句话：这件事现在到哪一步了",
 "timeline": [{"date": "MM-DD", "who": "张三", "text": "做了什么/说了什么"}],
 "open": ["还没解决的问题"],
 "actions": ["需要我做的事"]}
```

`timeline` 最多 8 条；每条点击打开对应邮件（模型返回邮件序号，鸿雁映射回 `mid`，不信任模型给的编号以外的东西）。不加密的会话结果按「会话 key + 最新邮件 mid」缓存，有新邮件时提示「有 N 封新邮件，重新总结」。

## 4. 写信助手

**入口**：撰写窗口工具栏新增「AI」按钮，菜单：润色、更正式、更简洁、更客气、译成英文、译成中文；以及「自定义要求…」（一句话，例如「语气坚决一点」）。

**作用范围**：有选中文字时只处理选中部分；没选中时处理正文中**自己写的部分**——不含签名（`.sig` 块）和引用的原邮件（「原始邮件」分隔线以下）。这两部分永远不发送给 AI。

**结果**：右侧（窄窗口时为下方）弹出预览，流式显示改写结果，下面三个按钮：「替换」「插入到下方」「放弃」；可以「再来一次」。替换时：

- 只处理纯文本段落。选区里有表格或图片时，菜单项置灰并提示「选区包含表格或图片，请只选文字」。
- 段落、换行保留；加粗、颜色等行内格式会丢失（预览上方说明这一点）。替换后提示条上有「撤销」（不用浏览器的 insertHTML：它会把最后一段和下面的签名合并）。

**提示词要点**：只改写，不增加事实、数字、日期、承诺；人名、编号、金额原样保留；翻译保持原意，不润色扩写。用户的草稿也放在随机标记里（草稿里可能粘贴了别人的邮件）。

## 5. 帮我起草回复

**入口**：阅读窗格 AI 面板「帮我回复」。

**流程**：

1. 第一次调用（JSON）：AI 读这封邮件（与「总结这封」相同的材料；若已有会话总结，也附上），给出 2～3 个回复方向：`[{"label": "同意并确认时间", "hint": "一句话说明"}]`。同时显示一个输入框「或者写下你想怎么回」。
2. 用户点一个方向（或输入意图，可再加补充，比如「周四前给」），选择「回复」或「全部回复」。
3. 打开撰写窗口：收件人、主题、引用由现有回复逻辑生成，和手动回复完全一样；正文位置显示占位「AI 正在起草…」并流式写入。生成完成后占位变为普通文字，用户随意修改。生成过程中可以「停止」。
4. 加密邮件：与「总结这封」相同，每次确认；回复时是否加密按现有规则（同事默认加密），AI 不改。

**AI 不能做的事**：不选择收件人、不加抄送、不决定是否加密、不发送。草稿里出现邮箱地址时（例如「请联系 xx@xx.com」），在正文中高亮，发送前检查也会提示。

## 6. 发送前检查

分两层：

**本机规则（每次发送都检查，不联网，毫秒级）**：在现有「没有主题」「提到附件却没附」之外增加：

- 日期：正文里的「X月X日 / YYYY-MM-DD / 下周X」等换算后早于今天，且上下文是「将于、请在、截止、之前」等将来语气 → 提示「正文中的 10月15日 已经过去」。
- 称呼：正文开头的称呼（「张总」「李工，你好」「Dear Tom」）里的名字，在主送人显示名里找不到 → 提示「称呼『张总』与主送人对不上」。
- 外部收件人：正文提到的邮箱地址 / AI 生成的草稿里出现了不在收件人中的外部地址 → 提示。

命中时一个对话框列出全部问题：「返回修改」/「仍然发送」。没有命中就不打扰。

**AI 检查（手动）**：撰写窗口「AI → 发送前检查」。送：主题、收件人显示名和域名、自己写的正文、附件文件名、今天日期。返回 JSON 问题列表（类型、原文片段、建议），点击定位到正文。只提示，不自动修改。
