# 鸿雁 · 待实现功能列表

更新：2026-10-22。这是开发排期的依据，先后以下面「开发顺序」为准；一项开工前先有设计文档，完成后在 `docs/releases/` 记录验证结果，并把它从这里移到 [已实现功能](已实现功能.md)。

状态：`设计中` → `待开发` → `开发中` → `待验收`；`想法` 表示还没有设计；`暂缓` 表示用户决定暂时不做。

## 开发顺序

**每次开发都从这张表里取：自上而下第一项「待开发」且依赖都已完成的。** 开工时把它改为「开发中」，做完（测试、演示走查、`docs/releases/` 记录）改为「待验收」，用户真机验收后从表里删掉，并移到 [已实现功能](已实现功能.md)。
用户提出新需求或要调整先后时，只改这张表（插入、移动、标「暂缓」），在下面「调整记录」写一行日期和原因；不在表外另排顺序。

## AI 功能的共同前提

- 公司已确认可以接入 DeepSeek 大模型 API（2026-10-17）。
- AI 后端做成可替换的 OpenAI 兼容接口（地址 + 模型名 + Key），以后可以换成内网部署的模型。
- API Key 和邮箱密码一样存 DPAPI，不写明文配置，Web UI 拿不到 Key。
- 加密邮件：公司不限制送 AI（2026-10-21 用户确认）。一次性设置「允许 AI 读取加密邮件」（默认关闭），可排除文件夹和发件人，命中排除的仍逐封确认。
- **AI 永远不能发信**，最多生成草稿，由用户确认收件人后发送；AI 提议的外部收件人醒目标出。
- 邮件正文一律当作不可信数据：先清洗成纯文本，用随机标记包起来，系统提示声明其中指令无效（防提示注入）。
- 自动功能由用户自己打开（例如任务中心的新邮件自动更新：只记进展，改状态要确认）。
- 错误只以固定错误码显示（`ui/messages.py`）；本地日志只记功能名、token 数、成败，不记 prompt 和回复。
