# v0.7 写信：签名图片（B5）、收件人组（F1）、正文 @某人（F2）

Branch `claude/v07-compose-cd1db2`. Nothing in this release talks to a new server API:
signature pictures go out through the v0.5 inline-image path, and recipient groups
and mentions are local only. No real-account check was run; the inline path was
verified send-to-self in v0.5 (`docs/releases/2026-10-18-compose-send-v05.md`).

## B5 签名图片（公司 LOGO）

- In 设置 → 邮件签名 there is a new 图片 button. You can also paste or drop a picture
  into the signature editor. Pictures and text are edited together.
- Click a picture (in the signature or in a mail body) to get a small bar with:
  - a width slider;
  - 小 / 中 / 大 / 原始大小;
  - 删除.

  The width is written both as the `width` attribute and as inline style, because mail
  clients read one or the other. A large logo starts at 240 px.
- Pictures stay in the signature HTML as `data:` URIs, in prefs inside the encrypted
  cache. Pasted HTML that points at network pictures has those pictures removed, with
  a hint. A recipient never has to load a remote picture.
- On send nothing new happens. The composer copies the signature into the body, and
  `compose/inline.py` turns each picture into its own MIME part:
  - plain mail: an inlined upload, which the server rewrites to `cid:` (verified in v0.5);
  - signed and encrypted mail: the S/MIME builder writes `multipart/related` with
    `cid:` references inside the signature or envelope.

  The same logo used twice becomes one part.
- Limits (`SIGNATURE_*` in `backend.py`), checked on save:
  - at most 5 pictures;
  - 1 MB of pictures in total;
  - 20 000 characters of text, not counting the pictures.

  Going over gives the fixed code `SIGNATURE_TOO_LARGE`. A broken picture gives
  `INVALID_SIGNATURE`. In both cases the old signature is kept. The page checks the
  same limits before it inserts a picture. The old silent cut at 20 000 characters,
  which would have broken a picture, is gone.

## F1 收件人组

- Groups are stored only in the encrypted cache kv (`recipient_groups`) and never go to
  the server. There can be up to 100 groups and up to 200 members per group. Names are
  1–40 characters and unique, ignoring case.
- Each member is set to 主送 or 抄送 on its own. If the same address appears twice, it
  is kept once, and 主送 wins.
- Codes: `INVALID_GROUP`, `GROUP_EXISTS`, `GROUP_LIMIT`, `GROUP_NOT_FOUND`.
- Editor:
  - Fields: the name, then a search box. The search box uses the same suggestions as the
    recipient field (recent contacts plus the company directory, marked 通讯录). A typed
    address is added with Enter.
  - Each member has a 主送/抄送 switch and a remove button.
  - 全部设为主送 / 全部设为抄送 change every member at once.
- Where groups appear:
  - Composer: a new 收件人组 link next to 抄送/密送 opens a menu. In it:
    - one click on a group applies it;
    - 将当前收件人存为组… saves the current recipients as a group;
    - 管理收件人组… manages the groups.
  - Settings: a new 收件人组 section to create, edit and delete groups.
  - Reader: the 更多 menu has 将收件人存为收件人组…. It takes the message's 主送/抄送,
    without the user's own addresses.
- Applying a group: `apply_recipient_groups` adds the members to the end of 主送/抄送.
  - It never adds an address that is already anywhere in the message, including 密送,
    or that an earlier group already added. So someone already in 主送 is not added
    again to 抄送.
  - Groups applied one after another add up.
  - A toast says how many people were added.
- A group only fills the fields. It never sends. Encryption is still decided by the
  page from the resulting recipients: colleagues are encrypted by default, and any
  external address turns encryption off.

## F2 正文 @某人

- Typing `@` in the body (at the start of a line or after a space or punctuation, so
  `name@company.com` does not count) opens the recipient suggestion list at the caret.
  - With nothing typed after the `@`, the list shows the people already on the mail.
  - After a name is typed, it shows the same `suggest` results as the recipient field,
    with current recipients first.
  - Keys: ↑/↓ move, Enter/Tab choose, Esc closes.
- Choosing a person inserts a highlighted `@姓名`. It is an inline-styled `<span>`
  (blue text on light blue), so it is plain HTML that any client shows.
  - If the person is not yet in 主送, 抄送 or 密送, they are added to 主送 (the user's
    decision), with a toast.
  - In the editor the mention is one non-editable unit. It is placed directly in the
    DOM, because `insertHTML` moved the non-editable span out of its paragraph.
- Deleting the last `@` of someone who is in 主送/抄送 asks 同时移除收件人？. Choosing
  移除收件人 takes them off.
- The copy that is sent drops the editing-only attributes (`contenteditable`,
  `data-mention`), so a 密送 person's address never shows up in the body. Drafts keep
  these attributes.
