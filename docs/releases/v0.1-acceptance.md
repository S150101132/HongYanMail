## 2. 自动化回归

命令：

```powershell
.venv\Scripts\python.exe -u -m unittest discover -s tests -v
```

结果：**99 项通过，0 失败，0 错误**，耗时 4.07 秒（`analysis/unittest-result.json`）。

执行环境说明：Qt WebEngine 的渲染子进程无法在 DSH 文件沙箱内创建（Chromium 报 `Check failed: 拒绝访问 (0x5)`），因此真实渲染器阅读测试需要在放宽沙箱下运行，并仅在测试驱动器里设置 `QTWEBENGINE_DISABLE_SANDBOX=1`。产品本身从不关闭 Chromium 自带沙箱。

本轮新增或修正的测试：

- `tests/test_desktop_messages.py`：每个可由代码抛出的错误码都必须有固定安全文案；异常自带的 URL、sid、密码、收件人不得进入界面文案。
- `tests/test_desktop_acceptance.py`：离线启动、最小窗口 1000×680、基准 1280×800、快捷键、1000 条列表的视图模型、筛选只声明“已加载”范围、未保存退出保护、会话失效后编辑内容保留、Unknown 结果不可重试。
- `tests/test_coremail_transport.py`：改用 `tests/fixtures/login/public-login-form.html` 合成样本，不再依赖被忽略的研究产物。

## 5. 已知限制

1. 真实独立登录、真实读取与自发自收需要本机密码，本轮未执行。
2. 证书“新实现加密 → 原客户端解密”未验证；企业 `cmsm` 扩展语义未解析。
3. 加密邮件的网络提交契约未验证，因此加密发送被显式阻止，且不会降级为明文。
4. 回复与回复全部入口保持禁用，直到引用头契约验证通过。
5. 不提供附件上传/下载/预览、已读回写、移动删除、服务端搜索、多账号、富文本。
6. 未做长时间运行、内存基线与 125–200% 缩放的正式目视验收。

## 6. 下一轮建议顺序

1. 完成一次真实交互登录与只读浏览，记录覆盖范围。
2. 用本机证书完成 Task 0 的真实解密并补齐 `analysis/certificate-compatibility.md` 的实测字段。
3. 在可控收件人下完成一次真实新信发送与收件箱 MIME 核对，验证 Unknown 恢复路径。
4. 取得回复引用头与加密提交契约的真实证据后再启用对应入口。
