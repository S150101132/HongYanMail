日期：2026-10-15

## 2. 自动化回归

命令：

```powershell
.venv\Scripts\python.exe -u -m unittest discover -s tests -v
```

结果：**107 项通过，0 失败，0 错误**，耗时 5.02 秒（`analysis/unittest-result.json`）。

执行环境说明：Qt WebEngine 的渲染子进程无法在 DSH 文件沙箱内创建（Chromium 报 `Check failed: 拒绝访问 (0x5)`），因此真实渲染器阅读测试需要在放宽沙箱下运行。测试模块自身会声明所需环境（offscreen 平台与测试驱动器的 `QTWEBENGINE_DISABLE_SANDBOX=1`）；产品本身从不关闭 Chromium 自带沙箱。

本轮新增或修正的测试：

- `tests/test_desktop_messages.py`：每个可由代码抛出的错误码都必须有固定安全文案；异常自带的 URL、sid、密码、收件人不得进入界面文案。
- `tests/test_desktop_acceptance.py`：离线启动、最小窗口 1000×680、基准 1280×800、快捷键不冲突、1000 条列表的视图模型、筛选只声明“已加载”范围、登录可仅用键盘完成（含回车提交）、加密发送阻止提示不会被自动保存状态覆盖、未保存退出保护、会话失效后编辑内容保留、Unknown 结果不可重试、多次会话失效只提示一次。
- `tests/test_coremail_transport.py`：改用 `tests/fixtures/login/public-login-form.html` 合成样本，不再依赖被忽略的研究产物。
- `tests/test_desktop_reader.py`：改为断言真实可读的 DOM 文本。原先断言 `loadFinished` 的布尔值为真，但正文中被正确阻止的远程图片会让 Chromium 报告加载失败，因此该断言衡量的是错误的东西。

## 3. 打包与启动

- 构建命令：`powershell -File packaging/build.ps1`
- 产物：`dist/CoremailDesktopPreview/CoremailDesktopPreview.exe`（onedir，含 Qt WebEngine 运行资源，450.3 MB / 2849 个文件）
- 启动验证：以 `--demo` 且 offscreen 平台启动，进程保持运行 25 秒未退出、未崩溃。

构建脚本现在会连续执行三项校验，任一项失败即让构建失败，避免“能启动但没有阅读器”的包被交付：

| 校验 | 脚本 | 本次结果 |
| --- | --- | --- |
| Qt WebEngine 阅读器可初始化 | `packaging/verify_webengine.py` | 通过，无 `DLL load failed` / `Check failed` |
| 产物不含证书、邮件样本或研究数据 | `packaging/audit_distribution.py` | 通过（0 命中），结果见 `analysis/distribution-audit.json` |
| 打包产物能启动并存活 | `packaging/smoke_check.py` | 通过 |

### 体积裁剪

初版打包为 573.7 MB。裁剪不是按猜测删文件，而是用 `packaging/bisect_qt_dlls.py` 在已知可用的包上逐个删除候选文件并重新运行诊断入口，只保留被证明“删掉仍可用”的部分，结果存于 `analysis/bundle-trim-experiment.json`。

- 已证明可删除 55 个文件（Qt Charts / DataVisualization / Graphs / Quick3D / Labs / Multimedia / Pdf / VirtualKeyboard / ShaderTools / SQL / Test / Sensors / SerialPort / WebSockets / RemoteObjects / Scxml / OpenGLWidgets、`opengl32sw.dll`、`QtOpenGL.pyd`、`QtQuickWidgets.pyd`）以及 Qt 翻译目录。
- 已证明**必须保留** `Qt6OpenGL.dll`：没有任何代码直接引用它，但删掉后 `QtWebEngineCore` 会以 `DLL load failed` 失败。这一条曾被错误的“只看进程是否存活”判据漏掉，原因是打包后的窗口程序在导入失败时会弹异常对话框而进程仍存活；现在的判据由带日志的控制台诊断入口给出。
- 结果：450.3 MB，比初版减少 123.4 MB。

体积仍有近半来自 `Qt6WebEngineCore.dll`（194 MB），它是正文隔离阅读的必需组件；本轮不承诺更小体积。

## 5. 已知限制

1. 真实独立登录、真实读取与自发自收需要本机密码，本轮未执行。
2. 证书“新实现加密 → 原客户端解密”未验证；企业 `cmsm` 扩展语义未解析。
3. 加密邮件的网络提交契约未验证，因此加密发送被显式阻止，且不会降级为明文。
4. 回复与回复全部入口保持禁用，直到引用头契约验证通过。
5. 不提供附件上传/下载/预览、已读回写、移动删除、服务端搜索、多账号、富文本。
6. 未做长时间运行、内存基线与 125–200% 缩放的正式目视验收。

## 6. 下一轮建议顺序

1. 完成一次真实交互登录与只读浏览，记录覆盖范围。
2. 用本机证书完成 Task 0 的真实解密并补齐 `analysis/certificate-compatibility.md` 的实测字段。
3. 在可控收件人下完成一次真实新信发送与收件箱 MIME 核对，验证 Unknown 恢复路径。
4. 取得回复引用头与加密提交契约的真实证据后再启用对应入口。
