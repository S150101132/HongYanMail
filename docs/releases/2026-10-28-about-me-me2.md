# Me2 · 「关于我」持续更新（2026-10-28）

设计：[2026-10-28-about-me-design.md](../superpowers/specs/2026-10-28-about-me-design.md) 第 5 节。接在 [Me1](2026-10-28-about-me-me1.md) 之上。

## 做了什么

三条路更新「关于我」，都不额外调用 AI：

1. **理解新邮件时顺带提议**：理解层的提示里，「关于我」每条带上编号（A1、A2…）；卡片多一个可选字段 `me`，最多 2 条，只在邮件明确说到用户本人的新情况时写，比如被指定为负责人或接口人、岗位或上级变了、有了新对接人、不再负责某事；更新已有的一条时写它的编号。提议不留在卡片上，进「关于我」顶部的「鸿雁想记住 N 条」：写明属于哪一组、取代哪一条，带「来源邮件」链接，逐条「记住 / 不用」。
   - 外部发件人只能提议「人」和「项目和系统」两组。
   - 已有的（生效中或待确认）不再提；点过「不用」的同一句话以后不再提（最多记 200 句）。
   - 最多 20 条待确认，超了先丢最旧的。待确认的不发给 AI。
2. **纠正时说为什么**：阅读条「⋯」菜单里多一项「告诉鸿雁为什么…」，写一句话、选记在哪一组（默认「工作方式」）。点「记住」后立即生效，记为「你纠正时写的」，并关联这封邮件。不改现有的一键改分类和「以后同类都这样」。
3. **问鸿雁里说「记住……」**：新工具 `remember_me`，出一张「记进『关于我』」卡片，写明分组、内容、取代哪一条，点「记住」才写入，记为「你在问鸿雁里说的」。只读 MCP 服务里没有这个工具。

被取代的条目不删，留在每组下面「以前的 N 条」里，写明哪天被取代，可以「恢复」；最多留 40 条。

## 代码

- `memory/profile.py`：条目状态 current / pending / past，`propose`、`keep_one`、`restore`、`refs`；`prompt(numbered=True)`。
- `ai/understand.py`：提示词 `me` 字段和规则，`parse(..., me_refs)`；`CARD_VERSION` 不变，只对新理解的邮件生效。
- `ai/tools.py`：`remember_me`（`REMEMBER_SPEC`）；`ai/agent.py`：规则 26。
- `app/backend.py`：`_about_propose`、`about_pending`、`about_restore`、`about_entry(src='fix', mid=)`、`assistant_remember_run`、`_about_known`；理解层和问鸿雁改用带编号的资料。
- `web/memory.js`（待确认框、以前、`meWhy`）、`understand.js`（菜单项）、`ai.js`（记住卡片）、`index.html`、`style.css`；`app/demo.py`：演示 AI 在「联调」邮件上提议一条。

## 验证

- 单元测试：`tests/test_about_me.py` 共 17 个，Me2 新增 5 个：
  - 提议：外部发件人只能提两组、已有的不再提、「不用」过的不再提、待确认上限、不发给 AI；
  - 记住后旧条目留作以前，可以恢复，编号与提示一致；
  - 理解新邮件：提示带编号和规则，提议进待确认、不留在卡片上，取代不认识的编号就不算取代；
  - 纠正时写的原因直接生效，来源邮件必须存在；
  - 问鸿雁：`remember_me` 先只出卡片，取代编号必须有效，执行一次后旧的留作以前，不能重复执行。
- 相关测试（理解、记忆、今天、助理、问鸿雁）共 133 个通过。全套 809 个，只有原有的 4 个错误（网络日志的测试顺序问题，与本次无关）。
- 演示走查：`HONGYAN_WALK_ME=1 python tools/screenshot_app.py build/me-shots`，截图 me2-pending、me2-kept、me2-menu、me2-why 正常。问鸿雁的「记住」卡片没有截图：演示 AI 不会调用这个工具，由单元测试覆盖。
- 真机（待用户）：
  1. 理解层跑几天后，看「鸿雁想记住」提的是否合理、会不会太多；
  2. 在阅读条点「告诉鸿雁为什么…」记一句；
  3. 在问鸿雁里说「记住，IPAM 现在由我对接」，看卡片和写入结果。

## 追加（2026-10-28，真机反馈）

- **批量删除**：「关于我」每条前面加了复选框，每组有「全选」；选中后上方出现「已选 N 条 · 取消选择 · 删除所选」，确认后一次删除（`about_remove`）。
- **重新生成不再换个说法重复**：真机重新生成后资料从 42 条涨到 80 条（满了），大量是已有条目换了说法，「人」和「工作方式」各有几条超出字数上限没有发给 AI。原因是 AI 起草时看不到已有资料，鸿雁只能按字面去重。现在把已有资料作为【已有的「关于我」】放进材料，并加了规则 7：意思相同的不要再写，换个说法也算重复；要更正已有的一条，就写完整的新一条并注明。测试：`test_regenerating_shows_the_ai_what_is_kept_and_many_go_at_once`。
- **真机资料整理（用户要求）**：80 条合并为 49 条（岗位 5、项目和系统 18、人 16、工作方式 10），四组都在上限以内。做法是合并重复、删去 2 条待办类和 2 条关系不明的联系人。整理前的加密数据原样备份在 `.tools`（不进 git）。
