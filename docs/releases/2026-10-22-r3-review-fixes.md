# 2026-10-22 · 回复只标已回复（R3a）、默认打开收件箱（R3b）、项目事实开关（R3c）、评审核实的六处修复（V1–V6）

依据：[独立评审](../reviews/2026-10-22-independent-review/01-产品评估总报告.md)（含 ChatGPT V1.0 方案）。评审中逐条到代码核实属实的问题都修了。用户说明平时邮件不多、不横跨很多项目，取舍按这个规模来：手动多点一下的成本很小，宁可多点也不要静默误判。方案 C 融合式首页、工作台、三类日期、注意力分级、AI 出站策略层等新概念暂不采纳。

## 功能

### R3a 回复只标「已回复」（取代 R1a 的自动已处理）

- 回复或转发一封「要我做」的邮件，发出后（含进发件箱、定时发送）只在这封上标「已回复 / 已转发」，它仍留在「要我做」和今天页里，排到还没回的后面。
- 提示「已回复，这封仍在『要我做』里。事情办完了就点『已处理』」，按钮一键标为已处理。
- 同一会话里更早的邮件不再连带标记；已处理的、AI 不确定的不动。
- 后端 `understand_answered(mid, how)`，卡片多一个 `answered` 字段（'reply' / 'forward'）。

### R3b 启动默认打开收件箱

- 设置 → 通用 →「启动时打开」默认「收件箱」，可改为「今天」；今天页保留在左栏最上面，用来把快到期的任务和「要我做」放在一起看。

### R3c 「记录项目事实」开关，默认关

- 设置 → AI 助手 → 工作记忆。关时理解新邮件只做 要我做 / 知会 / 可以忽略 的分类，不把已记的事实发给 AI，也不再记新事实；已记下的保留。
- 关时阅读条上的项目名不能展开「这个项目最近」，今天页和命令框不出现「本周概括」。

### V1–V6

| 项 | 修复 |
| --- | --- |
| V1 | 从今天页或它的子页在搜索框输入：离开今天页，列表是真正的搜索结果（原来标题变成「搜索结果」，列表还是原来的清单）。其他本机视图同样处理，和回车搜索一致 |
| V2 | 今天页空状态改为「已识别的事都处理完了」，说明只算 AI 读过的「要我做」和 3 天内到期的任务，带「去收件箱」；有 AI 还没读的邮件时，清单上方写「还有 N 封邮件 AI 还没读，暂时不在这里」（`today_overview` 的 `unread`） |
| V3 | 收件箱「要我做」的空状态改为「AI 读过的邮件里没有要你做的（还没读到的邮件仍在收件箱里）」 |
| V4 | AI 理解结果缺少「是否确定」或不是是/否时，一律按不确定（原来按确定，会进「要我做」） |
| V5 | 工作记忆的密钥丢失、或密钥对不上（没有一条记录能打开）时，报 `MEMORY_KEY_MISSING`，保留原文件，不新建密钥、不当作「没有记忆」；设置里显示原因。数据库还没有记录时照旧新建 |
| V6 | 收件人组超过 15 个时，菜单末尾「搜索全部 N 个组…」，按组名或成员找 |
