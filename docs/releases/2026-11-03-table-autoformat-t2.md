# T2 写邮件表格自动优化升级 · 实现与验证记录

日期：2026-11-03　状态：待验收（真机）
设计：[2026-11-03-mail-table-autoformat-design.md](../superpowers/specs/2026-11-03-mail-table-autoformat-design.md)（调研 6 个开源项目 + Codex 独立评审）
取代：U9 粘贴保留边框的整理部分、W8 AI 优化表格、U10 表格样式与手动调整（入口保留，内部重写）。

## 做了什么

从 Excel / WPS / Word / 网页复制的表格，粘贴进写信正文后自动排成商务邮件表格；复杂表格可再用「AI」深度优化。两层都只改样式，单元格内容、合并关系、行列数一律不变（每次排版前后比对内容指纹，不一致就放回原样）。

| 部分 | 实现 |
| --- | --- |
| 读剪贴板（`web/table/source.js`） | 按来源识别 Excel / WPS / Word / Google Sheets / 网页；内联 `<style>` 之前先读出 Excel 的 `x:num` 和 `mso-number-format`（CSSOM 会丢）；每格把有意义的格式（非白底色、非灰文字色、加粗、斜体、下划线、删除线、显式对齐）记在 `data-hy-src`，字体、字号、固定宽高、边框、`mso-*` 去掉 |
| 表格模型（`model.js`） | 占位网格（合并格占的每个位置指向同一格）、纯数据模型、内容指纹 |
| 类型识别（`types.js`） | 先信 Excel 自己的数字标记和格式；再解析文字：缺失值（N/A、-、无、待定…）不投票；金额（符号或 SAR/USD/RMB… 前后都行）、百分比、带单位数量（台、套、人天、GB…）、日期、时间、编号；编号证据（前导 0、长数字、电话、字母数字混合、文本格式、表头是 编号 / 电话…）优先于「能当数字」；列类型 90% 置信度，10 行以内容许 1 格例外；表头有 金额 / 费用 / USD… 的数值列算金额 |
| 结构识别（`structure.js`） | 行角色：标题 / 表头（可多行、分组表头）/ 分组 / 数据 / 小计 / 合计 / 备注 / 空行。表头从第一行「像普通行一样满」的行开始，再打分决定是不是表头（文字压在数字上、加粗、填色、合并、表头词、短词压在长文字上），分数不够就不设表头；没写「合计」但首列空、有数字的最后一行也认作合计 |
| 列宽与主题（`layout.js`） | canvas 按编辑器字体实测；数字、日期、编号、状态、短文字不折行，长文字分剩余宽度（下限 120px、上限 360px、按长度开方加权）；上限 640px；放不下也不硬压，编辑器里横向滚动。三套主题：简洁商务（默认）、紧凑数据（>20 行或 >8 列时自动）、正式报告（三线表）；颜色全是十六进制 |
| 渲染（`render.js`） | 每格样式按 主题 → 行角色 → 列对齐宽度 → 原表有意义格式 → 用户选择 重建；灰色表头带由主题接管、彩色表头带保留；Excel 表格样式的灰色斑马纹去掉、状态色保留；不折行用 `nowrap` 属性（Chromium 粘贴会去掉 `white-space`，Outlook 也只认属性） |
| 邮件兼容（`mail.js`，发送时） | 照 juice 的做法补 `align / valign / bgcolor / width / nowrap / cellpadding / cellspacing / border`，去掉 `data-hy-*` 和编辑器的滚动外框 |
| 控制（`controller.js`） | 分析 → AI 修正（只在本机把握 < 0.85 或 AI 把握 ≥ 0.9 时）→ 用户选择（永远优先）；粘贴后提示「撤销整理」；光标离开改过字的表格时重新排版（打字时不动）；同一选择在两张不同的表上出现，提示一次「以后粘贴的表格都…？」 |
| AI（`ai/tables.py`） | 发本机分析的结构摘要（每行角色 + 类型签名，相同连续行合并；表头、分组、合计、备注、类型异常行、中间抽样的原文；总量受限），AI 只回语义：行角色、列类型、表格用途、建议主题、一个重点列；温度 0；每张表按「摘要 + 模型 + 版本」缓存，重复点击复用；菜单「让 AI 重新考虑这张表」才重新问；表格改过则作废旧答案 |
| 手动调整（右键菜单） | 本列对齐 / 宽度、本行是（表头 / 分组 / 合计 / 普通）、表头对齐、底色、原表颜色 保留 / 去掉、表格样式（三套）、清除我的调整、AI 优化这张表 |
| 拖拽调整（`resize.js`） | 鼠标移到列或行的边线上变成调整光标，拖动改列宽 / 行高；拖动时只改这一列（行），松开后记为用户的选择（`data-hy-wpx` / `data-hy-h`）并重新排版，之后自动排版和 AI 都不覆盖；双击边线恢复自动；发送时写成 `width` / `height` 像素属性；「清除我的调整」一并清掉；签名和引用里的表格不能拖 |
| 偏好（设置 → 写信 → 表格） | 表格样式、表头对齐、日期对齐、保留原表颜色，可恢复默认；存本机，不上传 |
| 其他修复 | 加密邮件纯文本部分的表格用制表符分隔（原来 `1` 和 `53.91` 连成 `153.91`）；编辑器里表格单元格用 content-box，宽度和收件人看到的一致（原来全局 border-box 让每列少约 24px，列宽被浏览器重新分配）；AI 客户端支持温度参数 |

## 验证

- `tools/table_fixtures.py` 生成 12 个验收场景的剪贴板 HTML（合成数据）和期望结果；`tools/table_preview.py` 用 Qt WebEngine 加载真实脚本，生成优化前后对比图（`build/table-preview/`），逐张看过并据此修了 6 处问题（列宽余量、只有标签的列、斑马纹识别、金额列、手动对齐带表头、`white-space` 被粘贴去掉、box-sizing）。
- `tests/test_table_paste.py`（真实 Qt 页面）：12 个场景内容和合并完全不变；行角色和列类型符合期望；不超 640px 或按设计横向滚动；状态色保留、Excel 灰色去掉、无字体 / `mso-*` 残留；发送 HTML 无 `data-hy-` / `rgba` / `min-width`、有 `align` / `bgcolor` / 像素 `width` / `nowrap`；同一粘贴两次结果相同；撤销整理、手动选择保留与学习提示、过期 AI 答案作废。
- `tests/test_table_layout.py`（node）：32 种单元格、9 种 Excel 数字格式、8 张表的角色 / 类型 / 宽度。
- `tests/test_ai_tables.py`：摘要压缩与校验、AI 回复校验、温度 0、缓存与「重新考虑」、偏好校验、纯文本分隔。
- Codex 代码评审发现 3 个问题，已核实并修复、各加回归测试：单元格内多段落在纯文本里被连成一段；单独标色的表头格丢颜色；AI 摘要里混入了上次 AI 的答案，同一张表第二次点 AI 会换缓存键、重新请求。
- 拖拽：真实页面里模拟鼠标拖列边线 60px、行边线 30px，宽高准确、其他列不动，重新排版后保留，发送 HTML 有 width / height，双击恢复。
- Codex 第二轮评审（拖拽这一轮）又发现 3 个问题，已核实修复并加回归测试：表格改过字后点「撤销整理」/ AI「撤销」会连同修改一起丢掉（现在内容变了就不撤销并提示）；深色主题下浅色底的格子文字看不清（有底色的格一律配深色字）；表格里图片的尺寸被清掉（签名表格里的 LOGO 会变大）。
- 全量测试 872 个通过（跳过 11）。

## 遗留 / 未验证

- **真机未验**：在鸿雁里从真实 Excel / WPS 复制粘贴、发给自己后在 Outlook（Windows）、Gmail 网页、Coremail 网页、窄窗口和深色模式下看效果（设计 P6）。样例是按 Excel / WPS 剪贴板格式合成的，WPS 的真实剪贴板格式未核对。
- **AI 只用测试替身和演示模式验证过**：真实模型的回答质量、对复杂表格的改进幅度还没看；Mac 版 Excel 不带 `x:num`，只能靠文字解析。
- 大表（150 行）在测试机上整理约 370ms，超过设计里 150ms 的目标；体感可接受，后续可优化 `tbRowCells` 的重复扫描。
- 打字时不重排，光标离开表格才重排；在表格里删行列后立即重排。
- 学习偏好只在本次运行中计数（重启后从头数两次）。
