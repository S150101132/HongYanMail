# Z1 邮件时间统一（2026-11-08）

按[设计](../superpowers/specs/2026-11-08-mail-time-design.md)：邮件时间存成利雅得时间文字，显示和任务的「今天」按电脑所在时区。起因是同日的[搜索时区 bug](2026-11-08-search-date-zone.md)，之后用 `/improve-codebase-architecture` 评审定下。

- **`protocol/mailtime.py`**（新）：`STORE_ZONE` / `STORE_ZONE_NAME`（利雅得，全程序唯一一份，请求的 `tz` 标记也从这里来）、`stored(text, zone)`、`moment(text)`、`account_zone(name)`。`coremail.py` 的 `RESPONSE_ZONE`、`FIXED_ZONES`、`_in_response_zone` 去掉；`account_zone` 仍可从 `coremail` 导入。
- **缓存 `date_ts`**：按利雅得解析，排序、筛选、到期判断与电脑时区无关（原来按电脑时区解析）。
- **本地存档**（`archive/catalog.py`、`archive/pst.py`）：邮件时间写成利雅得文字，和服务器行一致（原来按电脑时区写）。已经建好的存档目录里，旧行仍是建目录时电脑时区的文字；电脑一直在利雅得，所以没有差别。
- **`_sent_date`**：改用 `mailtime`。**转为任务**带的邮件时间按电脑时区显示（原来固定利雅得）。
- **任务的「今天」**：`tasks/rules.local_today` 按电脑时区（原 `riyadh_today`，第二份 `RIYADH` 常量删掉）。
- **界面**：`app.js` 新增 `mailTime(text)`，按 `+03:00` 读存储文字；阅读栏右上角的收到 / 发出时间、列表在没有 `ts` 时、任务时间线里「关联邮件」的时间都改用它，浏览器按电脑时区显示。自动回复的起止时间（账号时区）不在此列，没动。

## 验证

- `tests/test_mailtime.py`：北京 16:50:12 存成利雅得 11:50:12、读不懂的原样；存储文字读成同一个 UTC 时刻，`date_ts` 与电脑时区无关；`account_zone` 行为不变；「今天」按给定时区（北京 06:30 已是第二天、UTC−5 还是前一天）和本机时区。先红（模块不存在）后绿。
- `tests/test_tasks.py` 原「按利雅得算今天」的用例改为「按电脑所在时区」。
- `mailTime()` 用 node 核对：`2026-11-08 11:50:12` → `08:50:12Z`，只有日期的按当天 00:00 利雅得。
- 全量 `unittest`：897 个通过（11 个跳过）。
- 没有在真窗口里看过；没有在改过电脑时区的环境里试过（这台电脑在利雅得，改前改后显示一样）。
