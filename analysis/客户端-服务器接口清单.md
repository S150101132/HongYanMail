## 1. 结论：接口数量

**客户端与邮箱服务器之间的接口共 4 类，主协议是 Coremail 私有 HTTP JSON-RPC。**

| 类别 | 数量 | 说明 |
| --- | ---: | --- |
| ① Coremail RPC 接口名（`func=模块:方法`） | **138** | 15 个模块命名空间；见第 3 节全表 |
| ② 非 RPC 的 HTTP/URL 端点 | **18** | 登录表单、SSO 跳转、附件/下载、组织同步、版本校验、EWS、自动发现等；见第 2 节 |
| ③ 备用传输适配器（非 HTTP） | **4 套** | IMAP4 / POP3 / SMTP / EWS(SOAP)；见第 5 节 |
| ④ 云侧第三方接口（非本域邮箱服务器） | **2** | `pcmail.coremail.cn/lunkr/...`，见第 2 节 |

按“桌面客户端真实可发起”收敛后的 ① 为 **130 个**：

- **128 个** 在 `CMClient.exe` 中作为独立字面量出现（静态确认内置）；
- 另 **2 个**（`oab:getHeadImageData`、`upload:directData`）虽未匹配到独立字面量，但由客户端自身日志证明被真实调用；
- 余 **8 个** 只出现在服务器端 Web 邮件页面的 JS bundle 中（`cim.common:clickLog`、`lp:getImg`、`mbox:composeF`、`mbox:editAttach`、`pab:addContactAvatarStd`、`pab:addContactKeyStd`、`pab:downloadContactSingleKey`、`pab:importContacts`），属于 **Web UI 专用，桌面客户端未使用**。

**实际被调用的接口：31 个**（在 73 个运行日志文件中累计出现 **57,498** 次 `func=` 调用），其余 99 个为已内置但本机日志未观察到的能力。

另有 2 项归属待确认（见第 7 节）：`pub:audit`（像 RPC）与 `action:createfolder|delete|movetofolder`（更像 `nf`/`upload` 请求的参数值而非接口）。

## 2. 传输层与固定端点

**主协议：** `POST https://<host>/coremail/s/json?func=<模块>:<方法>&sid=<会话>`，请求体为 Coremail JSON（`text/x-json` / `application/x-cm-json`），返回 `{code:"S_OK", var:...}`。

二进制中确认的协议常量：

| 证据 | 含义 |
| --- | --- |
| `/s/json?func=`、`&sid=`、`/coremail/s?func=` | RPC 与附件传送的两个入口 |
| `application/x-cm-json`、`text/x-json,application/x-cm-json,application/json` | 请求/响应 Content-Type 协商 |
| `text/x-json;charset=UTF-8;tz=UTC;useTypeCastExtension=1`、`application/x-cm-json;charset=UTF-8;tz=UTC` | 带时区与类型扩展的返回格式 |
| `Coremail.sid` / `Coremail.sid=` / `X-CM-AUTH-SID` | 会话凭证的 Cookie 与 Header 两种载体 |
| `&mboxa=` | 共享邮箱上下文参数 |

## 6. 证据、方法与边界

**证据源（全部只读）：**

| 源 | 说明 |
| --- | --- |
| `CMClient.exe`（40,818,224 字节，SHA-256 `a2cc47c5…37c5b`） | RPC 名字面量、URL 模板、协议常量、协议实现文件名 |
| `C:\Program Files\cmclient\app` | 网页层；REA `analyze_javascript_application` Evidence `ev_dab34191…1ad1` 证明其不直接发起服务端请求 |
| `C:\Users\wangbiao\AppData\Roaming\Cm\CMClient\logs`（73 个文件，51 MB） | 真实调用证据（31 个接口、57,498 次命中） |
| `analysis/web-login/*.js`（公司公开 Webmail bundle） | 交叉验证 8 个 Web UI 专用接口与别名路由（`!name:func`、`%name:func`） |

**产物：**

- `analysis/server-api-inventory.json`：原始提取（374 个候选标识符 + 每个来源文件）。
- `analysis/server-api-final.json`：分类后的 138 个 RPC 接口、模块汇总与标记。
- `analysis/runtime-observed-api.json`：运行日志中 31 个接口的调用计数。
- `analysis/native-api-clusters.json`：按字符串表邻近聚类，用于把 Coremail RPC 与 EWS/iCalendar 噪声分开。
- 提取脚本：`tools/extract_server_api.py`、`tools/analyze_native_api.py`、`tools/crosscheck_api.py`、`tools/build_api_final.py`。

**边界与不确定性：**

1. 静态字面量存在 ≠ 该版本一定使用；运行日志未出现的 99 个接口属“已内置、未观察到”。
2. 通过动态拼接生成的 URL/接口名不会被字面量提取捕获，因此 130 是**观察到的下限**，不是绝对上限。
3. 未抓包，未验证每个接口的 HTTP method、必填字段与返回 schema；`func=` 的 query 形态来自二进制模板，`/s/json` 以 POST 提交来自公开 Webmail 代码与历史分析。
4. EWS/IMAP/POP3/SMTP 的“存在”只由字符串与类名证明，未证明本账号启用或成功握手。
5. `oab:getHeadImageData`、`upload:directData` 属“日志确认、字面量未命中”，可能为运行时拼接。
6. Web UI 专用接口用的是 `!mail:func` / `%mbox/compose` 别名路由（映射到 `/coremail/XT/jsp/*.jsp`、`/coremail/common/mbox/compose.jsp`），与桌面客户端的 `/coremail/s/json` 入口不同，不应混为一谈。
7. **没有反编译级证据。** 本轮 REA 原生 lane 在 330 秒 provider 截止内未完成 `CMClient.exe`（40 MB PE）的默认自动分析，因此本清单不含函数级调用图、交叉引用或调度表还原；所有“内置”结论均来自镜像内的字面量与运行日志，而非控制流。

## 7. 待确认项

| 项 | 现状 | 需要什么证据 |
| --- | --- | --- |
| `pub:audit` | 二进制独立字面量，形态符合 RPC 名 | 一次带该 func 的调用或 xref 到调度表 |
| `action:createfolder` / `action:delete` / `action:movetofolder` | 与 `nf`/`upload` 字符串共处同一区域 | 判定为请求字段值还是独立 RPC |
| 各接口 HTTP method / 必填字段 | 仅少数有 URL 模板 | 同会话抓包或反编译协议分发函数 |
| EWS 是否对本账号启用 | 仅有实现证据 | 账号配置或 `autodiscover` 请求记录 |
