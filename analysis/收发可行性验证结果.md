# Coremail 独立收发验证结果

验证时间：2026-10-15 19:52（Asia/Riyadh）。

## 结论

**当前账户、服务器与网络环境下，独立自研程序可以正常密码登录 Coremail，读取邮件，并通过 Coremail Webmail HTTP 接口发送和收回普通测试邮件。**

本次验证使用自行创建的内存 CookieJar 与登录会话；密码由用户在本机遮挡输入框中提供。没有复用 Chrome、已有客户端的 cookie、sid 或设备 secret，没有调用官方客户端代发邮件，也没有依赖 IMAP/SMTP。

## 实测登录流程与修正

1. 新建内存会话，GET 公开登录页面，提取当前表单隐藏字段。
2. 普通 HTTPS 表单 POST 到 `/coremail/index.jsp?cus=1`。
3. 服务器返回 `location.replace(...)`，目标为同源 `/coremail/XT/index.jsp`，并携带登录会话参数。
4. 只解析该已观察到的字面量跳转，不执行服务器 JavaScript；通过同源 GET 完成登录导航。
5. 使用新会话调用文件夹、列表、原始邮件和写信接口。

此前两轮原型未处理 JavaScript 跳转，因此误报为需要认证交互；脱敏结构诊断定位后已修复。这不能解释为公司拒绝独立登录，也不是证书缺失。早期失败报告保留用于追溯，最终判断以本次 passed 报告为准。

发送使用公开写信代码对应的两步流程：POST `/coremail/common/mbox/compose.jsp`，先 action=continue 建立写信会话，再 action=deliver 发送。接收验证固定检查收件箱，其他文件夹的副本不能满足收回判定。

## 证书与未覆盖功能

已确认用户提供的 PFX 文件存在，当前没有读取其私钥、请求其密码、导入系统或使用其签名。此次普通邮件的收发不需要该 PFX。

尚未验证：附件上传与大附件、S/MIME/其他加密邮件解密与签名、组织通讯录、增量同步、会话续期、验证码/二次认证挑战、多账号、离线数据库，以及服务器其他部署版本。

Ghidra 12.1.4 已安装并通过 REA 引擎就绪检查；40.8 MB 客户端的默认完整冷分析在 900 秒上限内未完成，已停止并清理会话，没有取得原生反编译结果。**本轮收发可行性结论来自真实独立 HTTP 收发验证，不依赖原生反编译成功。**

此结论是兼容性实验结果，不代表完整客户端已完成。下一阶段可以在已实测的传输层之上设计邮件列表、阅读与写信流程，再扩展附件与同步能力。
